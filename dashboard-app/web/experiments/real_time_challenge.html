delay() · Blocking

TASK → WAIT → TASK → WAIT

Other code in the main execution flow cannot run until the delay finishes. Hardware interrupts can still occur during delay(); this first round uses no interrupt handler.

millis() · Non-blocking + Polling

TASK → CHECK TIME → CHECK INPUT

The main loop keeps executing, but polling only detects an input when you check it. Here, an event stays pending until checked; a short unlatched pulse could be missed in real hardware.

Interrupt · Event-driven

MAIN → ISR → RETURN → MAIN

An external event redirects execution to a short ISR, which sets a flag. The main loop then processes that flag.

millis() and interrupts solve different problems and can be used together. Round 3 still uses millis() for the periodic sensor and an interrupt for the emergency input. Interrupt timing here is a browser simulation, not microcontroller latency.
